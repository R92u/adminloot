# Dota Match Guess Admin 1.0

Полностью отдельный сайт администрирования для публичной игры `https://dotaguess.onrender.com`.

Панель не использует базу данных основного сайта напрямую. Её сервер обращается к закрытому API основного сайта по HTTPS. Административный API-секрет хранится только в переменных окружения админ-сервиса и не передаётся браузеру.

## Возможности

- редактирование имени, побед и количества ответов участников;
- добавление и удаление участников;
- полная очистка лидерборда и истории ответов;
- сброс и пересоздание матчей на текущий московский день;
- изменение количества матчей на сегодня — от 1 до 10;
- выбор одного или нескольких Dota-игроков;
- просмотр текущего набора матчей и фактических результатов;
- отдельная авторизация с защищённой HttpOnly-сессией;
- CSRF-защита административных операций;
- ограничение попыток входа.

## Render: новый отдельный Web Service

Создайте новый сервис, например `dotaguess-admin`.

Build Command:

```text
npm install
```

Start Command:

```text
npm start
```

Переменные окружения:

```env
NODE_ENV=production
TRUST_PROXY=true
MAIN_SITE_URL=https://dotaguess.onrender.com
MAIN_SITE_ADMIN_SECRET=тот_же_секрет_что_ADMIN_API_SECRET_основного_сайта
ADMIN_PANEL_PASSWORD=пароль_для_входа_в_админку
SESSION_SECRET=отдельная_случайная_строка_не_короче_32_символов
SESSION_TTL_HOURS=12
```

Используйте **три разные строки**:

1. `APP_SECRET` основного сайта — подпись игровых токенов;
2. `ADMIN_API_SECRET` / `MAIN_SITE_ADMIN_SECRET` — связь двух серверов;
3. `SESSION_SECRET` — подпись сессий админ-панели.

`ADMIN_PANEL_PASSWORD` — пароль, который вы вводите на странице входа.

После деплоя админка будет доступна по отдельному адресу Render, например:

```text
https://dotaguess-admin.onrender.com/
```

Проверка версии:

```text
https://dotaguess-admin.onrender.com/api/health
```

Ожидаемая версия: `1.0.0`.

## Порядок установки двух архивов

1. Разверните архив публичного сайта в существующем сервисе `dotaguess`.
2. Установите на нём `ADMIN_API_SECRET`.
3. Создайте новый Render Web Service из этого архива.
4. В новом сервисе задайте `MAIN_SITE_ADMIN_SECRET` с тем же значением.
5. Задайте отдельные `ADMIN_PANEL_PASSWORD` и `SESSION_SECRET`.
6. Выполните `Clear build cache & deploy` для обоих сервисов.

## Локальный запуск

Основной сайт должен быть запущен отдельно, например на `http://localhost:3000`.

```bash
cp .env.example .env
```

В `.env` укажите:

```env
MAIN_SITE_URL=http://localhost:3000
```

Затем:

```bash
node --env-file=.env server.js
```

Открыть:

```text
http://localhost:3000
```

Если основной сайт тоже использует порт 3000, для админки задайте другой `PORT`, например `3001`.
